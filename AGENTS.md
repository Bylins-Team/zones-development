> Если ты (человек или ИИ-агент) собираешься создавать или править зоны — **начни
> с официальной документации билдера**, а не с реверс-инжиниринга движка. Здесь
> собраны ссылки на неё и практические грабли, которых в OLC-доках нет.

## 2. Чего в OLC-доках НЕТ — практические грабли (проверено на движке)

Эти вещи официальная дока билдера не раскрывает (или раскрывает только для OLC, не
для правки через admin API / DG-скрипты). Все факты проверены по коду `~/repos/mud`.

### Двери и выходы
- У выхода-двери нужны **ДВА** поля: `keyword` (именительный) и `vkeyword`
  (винительный). В YAML это одно поле `keywords` формата **«именительный|винительный»**
  (разделитель `|`); если `|` нет — значение копируется в оба. `find_door`
  открывает дверь только когда **оба** поля заданы. Если задать лишь `keyword`
  (например, через `set_keyword`), `vkeyword` останется null и дверь не открыть по
  имени до перезагрузки (загрузчик ставит оба через `set_keywords`).
- `exit_flags`: `1` HASDOOR, `2` CLOSED, `4` LOCKED (дверь = `3`, запертая = `7`).

### Поля описаний предмета (важно не перепутать!)
- Имя в инвентаре (`short_description`) ← `names.nominative`.
- **Строка «лежит в комнате» (`description`) ← YAML-поле `short_desc`.** Сюда пишут
  «Кольчуга висит на стене», а **не** текст осмотра.
- Текст осмотра (по «осмотреть <предмет>») ← `extra_descriptions`.

### Предметы на полу комнаты (O-резет)
- Предмет, загруженный O-резетом на пол **без флага `NODECAY` (1<<13)**, сгниёт между
  ресетами зоны (движок пишет варнинг «без флага NODECAY»). Антуражные вещи
  (висят/лежат на месте) делают так: **ставят `NODECAY` И снимают флаг «взять»
  (`kTake`)** — иначе игрок утащит вечную вещь и бросит в поле.
- Альтернатива «лута на полу»: класть на мобов (death_load / экип E-резет) или в лавки.

### DG-триггеры: значение `narg` ЗАВИСИТ ОТ ТИПА
- **SPEECH и mob/wld COMMAND**: `narg` = режим `compare_cmd` — **0 = word_check**
  (срабатывает на любое слово из `arglist`, т.е. многословный список ОК), 1 =
  is_substring, иначе exact. Ставь **`narg = 0`** (не 100!).
- **OBJECT COMMAND**: `narg` = битовая маска местонахождения предмета (1 экип | 2
  инвентарь | 4 комната → обычно **7**), а `arglist` матчится как **один префикс**
  целиком (`strn_cmp`) → одно слово (для нескольких — `arglist = "*"` и проверка
  `%cmd%` в теле).
- **RECEIVE / DAMAGE / GREET / DEATH**: `narg` = процент срабатывания (100 = всегда).
- `return` **НЕ останавливает** скрипт: `if ... return 0 end; return 1` выполнит и
  `return 1`, перекрыв результат. Ставь `halt` после `return`, либо `if/else`.

### Полезные DG-приёмы
- Труп определяют **не по vnum**, а: `type == kContainer(15)` И `val3 ==
  CORPSE_INDICATOR(1)`; vnum исходного моба — в **`val2`** (у трупов игроков `-1`).
- `%room.objects%` — список UID предметов на полу комнаты; `calcuid`/`calcuidall`
  ищут UID по vnum; `oload/mload` кладут UID поднятого в **`%LoadedUid%`**.
- `dgcast` из триггера **предмета** кастует **от лица держателя-игрока** (предмет не
  удаляется) → так можно, например, навесить `charm` именно на игрока.
- Урон через `odamage/mdamage` по умолчанию `kPureDmg` и **не** вызывает
  DAMAGE-триггер цели (тот зовётся только для phys/magic/poison, damage.cpp) — удобно
  «пробивать» неуязвимость, сделанную DAMAGE-триггером.
- Оружие = `spec_param` с навыком владения (ESkill): kClubs141 kAxes142
  kLongBlades143 kShortBlades144 kTwohands146 kBows154. Без него «класс» = «!cooldown».

### Тестирование зоны
- Тестируют **морталом** (иммортал ≥31 уровня неуязвим некорректно), поставив зоне
  флаг «тестируется»: умереть нельзя (возрождаешься), агрессивные мобы не нападают,
  но пишут попытку, и по ним можно бить в ответ. Либо положить «походный алтарь
  возрождения» (obj vnum 1000) — возрождение там (с потерей хитов/обкаста).

### Admin API (если строишь не через OLC, а через web-admin HTTP API)
- `create_trigger` принимает поле `script` (компилит через OLC) — тело скрипта
  задаётся им. Привязка триггера: `update_mob/update_object/update_room` с полем
  `triggers: [vnum, ...]` (proto_script). `add_zone_command` поддерживает резеты
  M/O/G/E/P/D/R/T/V/F/Q. **vnum триггера должен быть в диапазоне зоны** (vnum//100).
- Создание ЗОНЫ через OLC/API не поддерживается (zone_table — отсортированный
  вектор + бинпоиск); болванку зоны заводят вручную + холодная перезагрузка.
  Резервные болванки (заведённые заранее) можно наполнять контентом через API
  без ребута.

## 3. Рецепты механик (проверено на движке)

### Предметы
- **Материал** — поле `material` (`update_object {material: N}`), EObjMaterial:
  kBulat1 kBronze2 kIron3 kSteel4 kForgedSteel5 kPreciousMetel6 kCrystal7 kWood8
  kHardWood9 kCeramic10 kGlass11 kStone12 kBone13 kCloth14 kSkin(кожа)15
  kOrganic16 kPaper17 kDiamond18. `0` = «НЕИЗВЕСТЕН» (показывается в осмотре).
- **Тип урона оружия** — `value3` (`type_specific.value3`), EDamageSource:
  kSlash3 (рубящее) kCrush6 (дробящее) **kPierce11 (колющее)**. Задаёт сообщения
  «рубит/крушит/колет» И возможность **заколоть** (backstab требует kPierce у
  оружия в правой руке!). Удобно выводить из навыка владения: короткие
  клинки/луки→kPierce, мечи/сабли/топоры→kSlash, дубины→kCrush.

### Флаги комнат (`update_room {room_flags:[p0,p1,p2,p3]}` — 4 плана, REPLACE!)
Битвекторы по планам (kIntOne→план1, kIntTwo→план2); читай старые флаги и
дописывай, иначе сотрёшь. Полезные (план 0): `kNoEntryMob 1<<2`, `kIndoors 1<<3`.
- **kNoEntryMob** — бродячие мобы не ВХОДЯТ (проверка при движении, не при
  резете). Игроков и очарованных питомцев НЕ блокирует, M-резет не ломает.
  Так держат патрули/зверьё вне корчмы/кузни/келий. **Проверяй связность:**
  !моб-комната на единственном пути отрезает мобам доступ к комнатам за ней —
  интерьерные кластеры флагуй целиком (или оставляй проходные открытыми).
- **kIndoors** — гасит погоду в комнате (`OUTSIDE = !kIndoors`). Без него внутри
  «Слабый ветер. Снегопад утих.». Ставь всем КРЫТЫМ (обычно sector `kInside`:
  избы, шатры, подкопы). Дворы (открытое небо) не трогай.

### Виртуальная комната *99 + сезонные/временные мобы
- Для КАЖДОЙ зоны движок **автоматически** создаёт служебную комнату
  `zone_vnum*100 + 99` (напр. 73899 для зоны 738) — при загрузке мада, сразу
  после загрузки комнат. В файлах мира её НЕТ (виртуальная). **Всегда считай,
  что *99 существует; создавать не нужно.**
- Моб с флагами появления `kAppearsWinter/Spring/Summer/Autumn`
  (`kAppearsDay/Night/Fullmoon`) вне своего сезона/времени автоматически прячется
  движком в *99-комнату, а в сезон возвращается в комнату M-ресета. Грузится он
  всегда; флаги управляют лишь видимостью. **Рецепт «сезонной пары»** (напр.
  медведь): шатун `kAppearsWinter`+не sentinel, обычный медведь
  Spring+Summer+Autumn+sentinel — оба M-ресетом в одну берлогу; движок показывает
  того, чей сезон. Кодировка флагов для admin API: `(plane<<30)|(1<<bit)` (plane 1:
  Winter bit10, Spring 11, Summer 12, Autumn 13). Примеры в мире: zones/1230, 1199.

### Флаги мобов
- **kStayZone (1<<6 = 64)** — моб не уходит за пределы своей зоны. Нужно
  боевым/осаждающим: иначе враги забредают через ворота к защитникам, а NPC
  «ассистят» друг другу против игрока (**у NPC нет фракций** — помогают любому
  NPC против PC). Sentinel-мобам не нужно (и так стоят).

### Питомец / charm чистым DG (НАДЁЖНО, без правки движка)
Комбинация двух команд (по совету А. Сердюкова):
```
dgaffect %ЦЕЛЬ% зачарован charm 1 40000 4   # charm-аффект БЕЗ спасброска
force %ЦЕЛЬ% следовать %actor.name%          # ставит ХОЗЯИНА (do_follow)
```
`dgaffect` — встроенная команда `script_driver` (доступна во ВСЕХ типах
триггеров, в т.ч. объектных). Синтаксис: `dgaffect <цель> <свойство> <спелл>
<значение> <длительность> [боепоз]`; `свойство` ищется в `apply_types`, затем в
`affected_bits` (там есть «зачарован»); `спелл` обязан резолвиться (`FindSpellId`
понимает и АНГЛ. имена — «charm» ок), иначе abort. `force` (=oforce/mforce) —
заставляет цель выполнить команду; `следовать %actor%` через `do_follow` ставит
master → моб ходит за игроком. Вместе = очарованный СЛЕДУЮЩИЙ питомец.
*Чище (когда вмержат [PR #3399](https://github.com/bylins/mud/pull/3399)):*
вместо `force` — сеттер `%ЦЕЛЬ.leader(%actor.id%)%` (по UID, те же проверки).
**Почему не иначе:** `dgcast 'charm'` упирается в спасбросок воли
(`(CHA-10)*4 + реморт*3` кастера) и бюджет хитов — у воина почти всегда провал;
`ospelladd` кладёт спелл в КНИГУ, не аффект; `otransform` в +стат-предмет не
поможет (апплаи действуют только НАДЕТЫМ, не в инвентаре); cha/realcha/статы в
DG доступны только для ЧТЕНИЯ; `dgaffect` сам по себе master НЕ ставит. Проверка
успеха: поля `%mob.ischarmice%` (1/0), `%mob.leader%` (uid хозяина),
`%mob.affectedby(charm)%`.

### DG: квесты, подкуп, прочее
- **Учёт квестов на игроке:** `%actor.quested(ID)%` → 1/0 (взят ли); запись —
  `eval tmp %actor.setquest(ID)%`; чтение текста — `%actor.getquest(ID)%`.
  **Скобки круглые `()`, не квадратные.** Так делают «намёк только на ещё не
  взятые квесты».
- **MTRIG_BRIBE (1<<12)** — срабатывает при передаче мобу ДЕНЕГ. `narg` = МИН.
  сумма; движок берёт ПЕРВЫЙ триггер, где `amount >= narg`, и останавливается.
  Для градации реакций по сумме делай ОДИН триггер `narg=1` и ветвись по
  `%amount%`. Доступны `%amount%`, `%actor%`.
- **Труп** определяют не по vnum: `type==kContainer(15)` И `val3==1`; vnum моба —
  в `val2`. `%room.objects%` — UID-ы на полу; `oload mob` ставит `%LoadedUid%`.
- Поле `%actor.vnum%` у игрока = `-1` (отличить PC от NPC в greet/random).

### Двери
- **Реальная запертая НЕОТКРЫВАЕМАЯ дверь:** в выходе `exit_info` =
  HasDoor1|Closed2|Locked4|**Pickroof8** = **15**, `key: -1`. `HasKey(-1)`
  всегда false → смертный не отопрёт; Pickroof → не взломать (движок честно
  пишет «вы никогда не сможете ЭТО взломать» — это его текст, не баг). Имморталы
  проходят (привилегия `kUseSkills` обходит замки). Дверь требует `keyword`
  «ном|вин» И комнату-цель `to_room` (нужна комната за дверью). Без Pickroof и с
  высокой `lock_complexity` — «интрига»: мастер-вор теоретически вскроет.

### Лавки (магазины)
- Лавки — ГЛОБАЛЬНЫЙ `lib/plrstuff/shop/shops.xml` (НЕ per-zone; OLC `sedit`
  НЕТ, API нет). Формат внутри `<shop_list>`:
  ```xml
  <shop currency="куны" id="MY_SHOP" profit="35" waste_time_min="120" can_buy="true">
      <mob mob_vnum="KEEPER_VNUM" />
      <item vnum="OBJ_VNUM" price="0" />   <!-- price=0 -> базовая цена прото -->
  </shop>
  ```
  `currency`: куны/ногаты/гривны/слава/лед. spec_proc `shop_ext` навешивается на
  keeper по `mob_vnum` НА СТАРТЕ → **нужен ребут**. Файлы зон пишет только
  серверный процесс (права), а `plrstuff/shop/shops.xml` правят напрямую (+ патч
  для продакшна).

### Имя зоны
- `update_zone {name: ...}` меняет имя ТОЛЬКО в памяти (живой сервер видит сразу),
  но **на диск НЕ пишет** (нет SaveZone — пробел API). Чтобы пережило ребут —
  триггерни SaveZone любым `add_zone_command`/`delete_zone_command` (они зовут
  `SaveZone`, который пишет `zone.yaml` из памяти). Трюк: клонировать существующий
  резет в конец и тут же удалить.
