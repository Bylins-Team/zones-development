## 2. Чего в OLC-доках НЕТ — практические грабли (проверено на движке)

Эти вещи официальная дока билдера не раскрывает (или раскрывает только для OLC, не
для правки через admin API / DG-скрипты). Все факты проверены по коду `~/repos/mud`.

### Двери и выходы
- У выхода-двери нужны **ДВА** поля: `keyword` (именительный) и `vkeyword`
  (винительный). В YAML это одно поле `keywords` формата **«именительный|винительный»**
  (разделитель `|`); если `|` нет — значение копируется в оба. `find_door`
  открывает дверь только когда **оба** поля заданы. Если задать лишь `keyword`
  (например, через `set_keyword`), `vkeyword` останется null и дверь не открыть по
  имени до перезагрузки (загрузчик ставит оба через `set_keywords`).
- `exit_flags`: `1` HASDOOR, `2` CLOSED, `4` LOCKED (дверь = `3`, запертая = `7`).

### Поля описаний предмета (важно не перепутать!)
- Имя в инвентаре (`short_description`) ← `names.nominative`.
- **Строка «лежит в комнате» (`description`) ← YAML-поле `short_desc`.** Сюда пишут
  «Кольчуга висит на стене», а **не** текст осмотра.
- Текст осмотра (по «осмотреть <предмет>») ← `extra_descriptions`.

### Предметы на полу комнаты (O-резет)
- Предмет, загруженный O-резетом на пол **без флага `NODECAY` (1<<13)**, сгниёт между
  ресетами зоны (движок пишет варнинг «без флага NODECAY»). Антуражные вещи
  (висят/лежат на месте) делают так: **ставят `NODECAY` И снимают флаг «взять»
  (`kTake`)** — иначе игрок утащит вечную вещь и бросит в поле.
- Альтернатива «лута на полу»: класть на мобов (death_load / экип E-резет) или в лавки.

### DG-триггеры: значение `narg` ЗАВИСИТ ОТ ТИПА
- **SPEECH и mob/wld COMMAND**: `narg` = режим `compare_cmd` — **0 = word_check**
  (срабатывает на любое слово из `arglist`, т.е. многословный список ОК), 1 =
  is_substring, иначе exact. Ставь **`narg = 0`** (не 100!).
- **OBJECT COMMAND**: `narg` = битовая маска местонахождения предмета (1 экип | 2
  инвентарь | 4 комната → обычно **7**), а `arglist` матчится как **один префикс**
  целиком (`strn_cmp`) → одно слово (для нескольких — `arglist = "*"` и проверка
  `%cmd%` в теле).
- **RECEIVE / DAMAGE / GREET / DEATH**: `narg` = процент срабатывания (100 = всегда).
- `return` **НЕ останавливает** скрипт: `if ... return 0 end; return 1` выполнит и
  `return 1`, перекрыв результат. Ставь `halt` после `return`, либо `if/else`.

### Полезные DG-приёмы
- Труп определяют **не по vnum**, а: `type == kContainer(15)` И `val3 ==
  CORPSE_INDICATOR(1)`; vnum исходного моба — в **`val2`** (у трупов игроков `-1`).
- `%room.objects%` — список UID предметов на полу комнаты; `calcuid`/`calcuidall`
  ищут UID по vnum; `oload/mload` кладут UID поднятого в **`%LoadedUid%`**.
- `dgcast` из триггера **предмета** кастует **от лица держателя-игрока** (предмет не
  удаляется) → так можно, например, навесить `charm` именно на игрока.
- Урон через `odamage/mdamage` по умолчанию `kPureDmg` и **не** вызывает
  DAMAGE-триггер цели (тот зовётся только для phys/magic/poison, damage.cpp) — удобно
  «пробивать» неуязвимость, сделанную DAMAGE-триггером.
- Оружие = `spec_param` с навыком владения (ESkill): kClubs141 kAxes142
  kLongBlades143 kShortBlades144 kTwohands146 kBows154. Без него «класс» = «!cooldown».

### Тестирование зоны
- Тестируют **морталом** (иммортал ≥31 уровня неуязвим некорректно), поставив зоне
  флаг «тестируется»: умереть нельзя (возрождаешься), агрессивные мобы не нападают,
  но пишут попытку, и по ним можно бить в ответ. Либо положить «походный алтарь
  возрождения» (obj vnum 1000) — возрождение там (с потерей хитов/обкаста).

### Admin API (если строишь не через OLC, а через web-admin HTTP API)
- `create_trigger` принимает поле `script` (компилит через OLC) — тело скрипта
  задаётся им. Привязка триггера: `update_mob/update_object/update_room` с полем
  `triggers: [vnum, ...]` (proto_script). `add_zone_command` поддерживает резеты
  M/O/G/E/P/D/R/T/V/F/Q. **vnum триггера должен быть в диапазоне зоны** (vnum//100).
- Создание ЗОНЫ через OLC/API не поддерживается (zone_table — отсортированный
  вектор + бинпоиск); болванку зоны заводят вручную + холодная перезагрузка.
