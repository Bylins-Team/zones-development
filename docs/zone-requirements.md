# Требования к зонам МУД "Былины"

## Обязательные компоненты зоны

### 1. Концептуальные требования

#### 1.1. Тематическая связность
- **Требование**: Зона должна быть основана на славянском фольклоре, русских сказках или оригинальной концепции, органично вписывающейся в мир Былин
- **Проверка**: Наличие описания фольклорных корней или обоснования темы
- **Автоматизация**: Проверка наличия секции "Фольклорная основа" в документации

#### 1.2. Оригинальность
- **Требование**: Зона не должна быть копией типичных fantasy-локаций (эльфийские леса, дварфские шахты)
- **Проверка**: Ручное ревью на уникальность концепции
- **Автоматизация**: Словарь запрещенных клише (эльфы, хоббиты, орки стандартного типа)

#### 1.3. Атмосферность
- **Требование**: Зона должна создавать яркую, запоминающуюся атмосферу
- **Проверка**: Наличие детализированных описаний визуала, звуков, запахов
- **Автоматизация**: Подсчет сенсорных деталей (минимум 3 типа чувств на зону)

### 2. Структурные требования

#### 2.1. Размер зоны
- **Минимум**: 5 комнат
- **Оптимум**: 10-30 комнат
- **Максимум**: 50 комнат (без особого обоснования)
- **Автоматизация**: Подсчет количества комнат в файле зоны

#### 2.2. Связность
- **Требование**: Все комнаты зоны должны быть достижимы
- **Проверка**: Граф проходимости
- **Автоматизация**: Алгоритм поиска в глубину/ширину от точки входа

#### 2.3. Топология
- **Требование**: Зона не должна быть линейной (если это не обосновано)
- **Проверка**: Наличие развилок и альтернативных путей
- **Автоматизация**: Анализ графа (среднее количество выходов на комнату > 2)

### 3. Контентные требования

#### 3.1. Мобы (NPC)
- **Минимум**: 3 уникальных типа мобов
- **Требование**: Мобы должны соответствовать тематике зоны
- **Характеристики**: Для каждого моба должны быть определены:
  - Имя и краткое описание
  - Детальное описание (examine)
  - Уровень и базовые характеристики
  - Агрессивность и поведение
  - Лут (что выпадает)
- **Автоматизация**: Проверка наличия всех обязательных полей

#### 3.2. Объекты
- **Минимум**: 2 уникальных объекта
- **Типы**: Оружие, доспехи, зелья, квестовые предметы, декорации
- **Характеристики**: Для каждого объекта:
  - Название и тип
  - Описание
  - Характеристики (для экипировки)
  - Редкость
- **Автоматизация**: Проверка обязательных полей, баланс характеристик

#### 3.3. Квесты (опционально, но желательно)
- **Требование**: Хотя бы один мини-квест или цепочка действий
- **Типы**: Сбор предметов, убийство босса, головоломка, исследование
- **Автоматизация**: Проверка наличия описания квеста

### 4. Текстовые требования

#### 4.1. Описания комнат
- **Требование**: Каждая комната должна иметь:
  - Короткое название (до 50 символов)
  - Детальное описание (100-500 символов)
  - Список очевидных выходов
- **Качество**: Описания должны быть:
  - Атмосферными
  - Грамматически правильными
  - Без опечаток
- **Автоматизация**:
  - Проверка длины описаний
  - Проверка орфографии (aspell/hunspell для русского)
  - Проверка на использование сенсорных деталей

#### 4.2. Стиль текста
- **Требование**: Единый стиль повествования
- **Избегать**:
  - Современных слов и жаргона
  - Английских заимствований (где возможно)
  - Анахронизмов
- **Автоматизация**: Словарь нежелательных слов

#### 4.3. Грамотность
- **Требование**: Отсутствие орфографических и грамматических ошибок
- **Автоматизация**: Проверка орфографии, базовая проверка грамматики

### 5. Игровой баланс

#### 5.1. Уровень сложности
- **Требование**: Зона должна быть привязана к определенному диапазону уровней игроков
- **Параметры**:
  - Минимальный уровень
  - Рекомендуемый уровень
  - Максимальный уровень
- **Автоматизация**: Проверка соответствия уровней мобов и наград

#### 5.2. Награды
- **Требование**: Лут и награды должны соответствовать сложности
- **Проверка**: Баланс опыта/золота/предметов
- **Автоматизация**: Формулы баланса (опыт/уровень моба, стоимость предметов)

#### 5.3. Опасности
- **Требование**: Соответствие опасностей уровню зоны
- **Типы**: Агрессивные мобы, ловушки, environmental hazards
- **Автоматизация**: Проверка урона относительно среднего HP персонажей уровня зоны

### 6. Техническая корректность

#### 6.1. Формат файлов
- **Требование**: Соответствие техническому формату зоны
- **Автоматизация**: Парсер формата, проверка синтаксиса

#### 6.2. Уникальность ID
- **Требование**: Все ID комнат, мобов, объектов должны быть уникальны
- **Автоматизация**: Проверка на дубликаты ID

#### 6.3. Ссылочная целостность
- **Требование**: Все ссылки (на комнаты, мобов, объекты) должны быть валидны
- **Автоматизация**: Проверка существования всех referenced ID

## Процесс валидации

### Автоматическая проверка (Phase 1)
1. Синтаксис формата файлов
2. Структурная целостность
3. Количественные метрики
4. Орфография
5. Игровой баланс (базовые проверки)

### Ручная проверка (Phase 2)
1. Качество текста и атмосферности
2. Тематическая связность
3. Оригинальность концепции
4. Игровой баланс (детальная оценка)
5. Fun factor
